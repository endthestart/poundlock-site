Poundlock

Run models on your own machines and give every app one place to reach them.
Get startedView on GitHub

The problem it solves

Section titled “The problem it solves”

Say you have a couple of machines that can run models: a desktop with a decent GPU, maybe a Mac with a lot of memory. Your editor wants a small, fast model for completions. A chat app wants a bigger one. A coding agent will happily keep a GPU busy for an hour. Each of them needs an address and a key, and when two of them reach for the same GPU at once, one of them gets an error.

Poundlock sits in front of those machines and gives everything one OpenAI-compatible address. Each app gets its own token, with only the permissions it needs. If a model is busy, the request waits its turn instead of failing. If the machine is asleep, Poundlock wakes it up first.

It can also take a longer coding job, run it with a local agent in a locked-down container, and give you back a patch along with the results of the checks you asked for. You decide whether to apply it.

Who it’s for

Section titled “Who it’s for”

One person or a small team that owns its hardware and would rather keep prompts and code on it. Your model servers stay yours: Poundlock talks to llama.cpp, Ollama, vLLM or anything else that speaks the OpenAI API, and it leaves model downloads and GPU drivers to you.

It’s not a hosted service, and it’s not built for strangers sharing one install. It won’t place models across a cluster for you either. If that’s what you need, the comparison points to projects that do it well.

What you need

Section titled “What you need”
  • A Linux x86_64 machine with Docker for the server.
  • At least one model server you already run.
  • For machines that sleep, Wake-on-LAN. The optional node agent is supported on Linux; macOS and ARM nodes work but are still a preview.

The getting started guide goes from hardware to a first working request.

The other pieces

Section titled “The other pieces”

Poundlock is one of three projects that work together, and each one stands on its own.

  • Toolkit tells you which models, runtimes and settings actually hold up on your hardware, before you trust them with real work.
  • Dispatch is a desktop app and a terminal client. You talk to a project manager, agree a plan, and it hands the tasks to local models through Poundlock, then checks what comes back before accepting it.

How they fit together has the longer version, and why I built this has the story behind it.

Where things stand

Section titled “Where things stand”
